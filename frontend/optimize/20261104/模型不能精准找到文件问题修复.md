## 二、搜索实现重写

[search.ts](file:///jun/ai-generate-code/frontend/src/main/ai/tools/search.ts) 不再自己递归遍历，改为 spawn ripgrep：

- `glob`：`rg --files --glob=<pattern> --sort=modified`，形状对齐 harness 的 [buildGlobCommand](file:///jun/ai-generate-code/deepseek-harness/packages/fs/tool-fs-search/src/glob.ts#L93-L122)。
- `grep`：`rg --json --regexp=<pattern>`，按 NDJSON 解析 path/line_number/lines。
- `glob` 用 `--no-ignore --hidden` 并排除 `.git` 等 VCS 目录（为了列全文件），不传 `path` 时再按目录名剪掉 `node_modules/bin/target/out/dist/...`；`grep` 与上游一致，只带 `--json`、pattern 与调用方的过滤，其余走 ripgrep 默认语义（遵守 `.gitignore/.ignore`，跳过隐藏文件），不再读 `.gradle` 这类会被构建进程独占锁定的缓存。两者范围不同是有意为之：glob 能看到隐藏/被 ignore 的文件，grep 看不到。
- 上限不再是“扫描预算”：gl‍ob 200 条、grep 100 条，超出时结果里明确写「共 N 条，仅显示 X 条」，glob 超限按顶层目录轮转采样（避免一个大子项目霸占全部名额）。
- `path` 支持文件：`grep` 直接搜单文件，`glob` 只判断该文件，不再全仓重走。
- `--no-config` 防止宿主 `RIPGREP_CONFIG_PATH` 注入 `--pre`；输出上限 20MB、工具超时 30s、`ctx.signal` 中止时直接 kill 子进程。
- 路径解析：`createRequire(__filename).resolve('@vscode/ripgrep-<platform>-<arch>/bin/rg')`，再把 `app.asar` 换成 `app.asar.unpacked`。不直接 import `@vscode/ripgrep`，因为 1.18 是纯 ESM，主进程 CJS 打包后 require 不了。

顺带把 [prompt.ts](file:///jun/ai-generate-code/frontend/src/main/ai/prompt.ts#L38-L47) 的提示更新成新语义（堆栈里的 FQCN 可直接换算路径先 read；看到“仅显示/共 N 条”不要断言文件不存在）。

## 四、你需要知道的

1. 重启 `npm run dev` 让新工具生效（主进程代码变了）。
2. 默认不再返回 `bin/`、`target/` 里的 `.class`——这是有意的降噪，真要搜就传 `path`。
3. 在真实项目（`E:\junworkspace8`）里再试 `glob **/ZHYGLoanbillPlugin.java`，应该一步命中；全仓 `grep` 也应从 10s+ 降到百毫秒级。
4. 如果 Windows 包是在 Windows 上打的，`@vscode/ripgrep-win32-x64` 会随 `npm install` 自动装好；在 Linux 上交叉打则由 `dist.mjs` 自动补装。

唯一和 harness 不同的一处：它超限时会把完整结果写进 spill 文件并给出取用路径，我们没有 spill 存储，所以只给「共 N 条 / 仅显示 X 条」的提示。要的话可以再加一个落到临时目录的 spill。
